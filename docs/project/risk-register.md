| R-014 | Native OAuth could conflict with Supabase provider state, leak a verifier, accept a forged or wrong-project token, over-fetch JWKS for concurrent unknown keys, persist an access token, send text merely because a user is signed in, or leave the UI blocked when the callback never reaches Fluent | High | Use the Supabase social authorize endpoint only and never inject application `state`; retain one fresh PKCE S256 verifier/challenge and one exact bounded callback on `127.0.0.1` port 0; normalize provider errors; dispose the listener and clear SigningIn before terminal UI notification; enforce a total timeout; keep access tokens memory-only and refresh token in Windows Credential Manager; bind OIDC/JWKS to mandatory trusted issuer/audience and coalesce overlapping unknown-kid refreshes; preserve separate Cloud activation and consent | Mitigated and accepted for Phase 07B on 2026-07-22: core OAuth and four manual checks PASS, 12 OAuth, 13 JWT, 301 full tests and 33 hook tests pass; final Judge ALLOW and user closure recorded |
| R-015 | The physical Fluent rename may be lost, partially committed or make a future change set unauditable because Git sees old paths deleted and new paths untracked | High | Preserve the 301-change baseline, do not stage or clean it during unrelated work, reconcile only in a separate approved rename/Git-hygiene task with manifest, build/test and human review before packaging or publication | Open — 117 modified, 155 deleted and 29 untracked entries observed on 2026-07-22 |
